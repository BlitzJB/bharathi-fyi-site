For years, my job was to make other engineers faster: golden paths, paved
roads, internal platforms that turned "how do I deploy this?" into a
non-question. Then LLMs showed up, and it turned out the job barely changed —
only the raw material did.

## The transferable parts

Platform engineering is fundamentally about **taming unreliable substrates**
so product teams don't have to think about them. Swap "flaky cloud APIs" for
"non-deterministic models" and the playbook holds:

- Put a stable interface in front of a messy dependency.
- Make the failure modes observable before making them rare.
- Treat cost as a first-class dimension, not an afterthought.

The same instinct that makes you wrap a cloud SDK in a retry-aware client
makes you wrap a model call in evals and fallbacks.

```ts
// The shape is familiar: a boundary around something unreliable.
export async function answer(question: string): Promise<string> {
  const result = await streamText({
    model: process.env.CHAT_MODEL ?? "openai/gpt-oss-120b",
    system: buildSystemPrompt(),
    prompt: question,
  });
  return result.text;
}
```

## The parts that don't transfer

Determinism, mostly. A platform either provisions the database or it doesn't.
A model *usually* answers well. Learning to design for "usually" — evals over
unit tests, distributions over assertions — is the real retraining.
