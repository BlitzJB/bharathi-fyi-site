# Post

Nine models. All collapsed within 16 steps of real tool use.

Some context: an agent workflow is a chain of dependent steps. Look something up, act on the result, act on that result. A new study measured what happens to reliability as those chains grow: nine models, from 1.2B open-source to deployed proprietary systems, across 10,664 trajectories and four task families. On the genuinely agentic tool-use tasks, in the paper's own words: "every model tested, including widely deployed systems, falls from near-perfect success to near zero within sixteen steps."

The numbers that matter, from Shubhra Mittal's paper on arXiv this week:

→ Success follows a geometric law. Per-step reliability compounds, and it plateaus below 1.0 at every model scale. Collapse at some horizon isn't a risk. It's a guarantee. The only question is which step.

→ The benchmark-to-production gap runs from 0.42 at GAIA-length horizons to 0.24 at hundred-step production horizons. Leaderboards measure the part of the curve where everything still works.

→ Bounding the context made decay steeper (logit slope -0.69 vs -0.44, p=3x10^-6). The standard "keep the window small" production trick accelerates the failure it's meant to prevent.

Rot follows step count; context length barely matters.

The takeaway if you run agents anywhere: aggregate pass rates don't predict survival. Budget reliability per step, the way SREs budget errors.

What's the longest dependent-step chain you trust an agent with today?

P.S. Paper in the first comment. The released trajectories are worth poking at.

# Post (variant B)

LLM agents don't fail randomly. They rot on a schedule.

Nine models, 10,664 trajectories, and not one survived past step 16 on real tool-use tasks. That's from a paper Shubhra Mittal put on arXiv this week, measuring how agent reliability behaves as workflows get longer. In the paper's own words: "every model tested, including widely deployed systems, falls from near-perfect success to near zero within sixteen steps."

The mechanism is the same math that runs uptime SLAs. An agent has a per-step reliability, call it p, and an n-step workflow succeeds at roughly p^n. Bigger models push p up, but it plateaus below 1.0. Which means collapse at some horizon isn't a risk. It's a guarantee. The only question is which step.

The part that breaks intuition: trimming the context to keep the agent "focused" steepened the decay (logit slope -0.69 vs -0.44, p=3x10^-6). Rot follows step count; context length barely matters. The standard production trick attacks the wrong variable.

And leaderboards won't warn you. The benchmark-to-production gap runs from 0.42 at GAIA-length horizons to 0.24 at hundred-step production horizons: benchmarks live on the part of the curve where everything still works.

The takeaway if you run agents anywhere: aggregate pass rates don't predict survival. Budget reliability per step, the way SREs budget errors.

What's the longest dependent-step chain you trust an agent with today?

P.S. Paper link in the first comment.
